# 揪團訂飲料 App 產品需求文件（PRD）

- 版本：v1.0（草稿）
- 更新日期：2026-10-15
- 平台：網頁 App（PWA）

---

## 1. 產品概述

### 1.1 一句話說明

讓朋友之間可以快速揪團訂飲料：決定喝哪家、誰要一起、湊免運、追蹤誰點好了、誰還沒還錢。

### 1.2 背景與問題

朋友之間一起訂飲料時，常見的問題有：

- 沒有一個共同的群組，每次揪團都要一個一個私訊。
- 不知道誰已經在平台上點好了，團主要一直追問。
- 外送要湊到免運門檻，但不知道目前湊了多少。
- 團主先墊錢後，很難記得誰還了、誰還沒還。
- 每次都忘記自己上次點了什麼。

### 1.3 產品定位

這個 App **不負責點餐，而是負責「揪」**。點餐、選規格、結帳都交給既有的點餐平台（你訂、Uber Eats、foodpanda 或店家自有平台），App 專心處理平台沒有做好的事：揪團、湊免運、追蹤點餐狀態、分帳。

### 1.4 目標

- 團主可以在 1 分鐘內開好一團並分享出去。
- 朋友點開連結後，不需要註冊就能加入。
- 團主隨時知道誰點好了、湊了多少錢、誰還沒付款。
- 同一群人可以輕鬆再揪下一次（續團）。

### 1.5 非目標

- 不做點餐與金流，不串接任何平台的下單 API。
- 不自動抓取（爬取）平台上的菜單、價格、運費或免運門檻（原因見 7.1）。常見店家與飲料品項改為手動整理建立，運費與門檻由團主手動填寫。
- 第一版不做即時聊天室。

## 2. 使用者與角色

使用對象是會一起訂飲料的朋友，他們**不一定有共同的群組**。

| 角色 | 說明 | 要做的事 |
| --- | --- | --- |
| 團主 | 發起這一團的人，任何人都可以當團主 | 選店家、在點餐平台開團並取得揪團連結、設定結單時間、分享連結或通知團友圈、先付款並留下收款帳號、提醒還沒點或還沒付款的人 |
| 團員 | 加入這一團的人 | 看到開團卡片、跳到平台點餐、回來按「點好了」並輸入金額、依收款帳號還錢給團主 |
| 取餐人（自取） | 負責到店拿飲料的人 | 在取餐時間到店取餐，到店時在團頁面發通知 |
| 收件人（外送） | 負責收外送的人 | 在指定地點收飲料 |

## 3. 名詞定義

| 名詞 | 定義 |
| --- | --- |
| 團（臨時團） | 一次訂飲料的活動。由團主開團產生連結，結單後即結束。 |
| 揪團連結 | 點餐平台（你訂、Uber Eats、foodpanda 等）提供的群組訂單連結，由團主貼進 App。 |
| 邀請連結 | App 產生的連結，點開即可加入這一團。 |
| 團友圈 | 一團結單後，該團成員自動組成的固定名單，用來續團。 |
| 續團 | 團友圈中任何人發起新的一團，並通知圈內成員。 |
| 點好了 | 團員在平台完成點餐後，回到 App 回報的狀態，同時輸入金額。 |

## 4. 核心流程

一次揪團從開團到分帳共六步，其中點餐和付款發生在點餐平台上。

1. **開團**：團主在 App 選店家（第二版起可先發起投票讓大家選），到點餐平台開團並取得揪團連結，回到 App 填寫開團資訊。
    1. 選擇取餐方式：自取或外送。
    2. 填寫結單時間；外送另填免運門檻、運費與送達地點，自取另填取餐時間、地點與取餐人。
2. **分享**：團主把邀請連結私訊給想揪的人或貼到 IG；續團則直接推播通知勾選的團友圈成員。
3. **點餐**：團員按「點我加加」跳到平台點餐，回來按「點好了」並輸入金額。
4. **結單**：結單時間到，卡片顯示已結單；結單前團主可以提醒還沒點的人。
5. **取餐／收餐**：自取由取餐人到店領取；外送由收件人收取。
6. **分帳**：團主先付款，團員依團主的收款帳號轉帳，轉帳後標記已付款。

## 6. 非功能需求

- **隱私**：收款帳號只傳給符合權限的成員，不出現在邀請連結的預覽（Open Graph）中，也不能只靠前端隱藏。
- **低門檻**：從點開邀請連結到加入團，不超過兩個步驟（輸入暱稱、加入）。
- **裝置**：以手機瀏覽器為主，支援 iOS Safari 與 Android Chrome；可以加入主畫面（PWA）。
- **推播限制**：iOS 必須將網站加入主畫面才能接收 Web Push，因此所有通知都要有複製連結的替代方式。
- **時間**：結單倒數與截止時間以台灣時間（UTC+8）顯示。

| 推播 | Web Push | 續團、投票、結單提醒 |

### 7.1 決策紀錄

- **做網頁而不是原生 App**：邀請連結點開就能用，朋友不需要先安裝，最符合臨時團的使用情境。
- **第一版不做聊天室**：即時聊天的工程量大，改用不需即時同步的留言串，先把揪團核心功能做好。
- **不自動讀取平台資料**：外送平台沒有開放給一般開發者的公開 API，爬蟲違反服務條款且容易失效，運費與門檻也會因使用者的地址、時段與會員身分而不同，因此改由團主手動填寫。

## 9. 權限規則

收款資訊獨立放在 `round_payment_info`，以 Supabase Row Level Security 限制讀取：只有在該團 `ordered = true` 的成員才能讀取。匿名成員一樣擁有使用者 ID，因此這條規則同樣適用。

```sql
create policy "點好了才看得到收款帳號"
on round_payment_info for select
using (
  exists (
    select 1 from round_members
    where round_members.round_id = round_payment_info.round_id
      and round_members.user_id = auth.uid()
      and round_members.ordered = true
  )
);
```

其他規則：

- 只有團主可以修改開團資訊、移除成員、寫入收款資訊。
- 團員只能修改自己的「點好了」、金額與付款狀態。
- 被移出團的成員，`round_members` 紀錄會被刪除，因此也失去讀取收款資訊的權限。
- 評價：所有人都可以讀取；只有非匿名的使用者可以新增評價，且只能修改或刪除自己的評價。
- 飲料品項：只有管理者可以新增、修改或標記停售，一般使用者透過回報（F-88）提出。

## 10. 版本範圍與開發順序

### 10.1 第一版（P0）

開團卡片（自取／外送、多平台連結）、點餐狀態與金額回報、分帳與收款帳號、臨時團與匿名加入、團友圈與續團通知、留言串、店家頁與店家清單、品牌與飲料品項、飲料評價。

### 10.2 開發順序

每一步完成後都要實際找朋友試用。

1. 匿名登入、開團、分享邀請連結、點連結加入。
2. 「點好了」與金額回報、留言串、提醒。
3. 免運進度條、分帳與收款帳號（含 RLS）。
4. 團友圈、續團、Web Push 與複製連結的替代方式。
5. 品牌頁、飲料品項資料、飲料評價。
6. 第二版：結單後評價提示、品項回報、「我上次點的」、投票選店。

### 10.3 之後再做（P2）

飲料日行事曆、即時聊天室、朋友推薦與排行、近日優惠、LINE 登入。

## 11. 成功指標（建議）

- 朋友實際使用 App 揪團的次數。
- 續團佔所有開團的比例，用來確認團友圈是否有價值。
- 團員從點開邀請連結到加入團所需的時間。
